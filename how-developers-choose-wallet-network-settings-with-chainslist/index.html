How developers choose wallet network settings with chainslist

Chainslist shows why developers must match a wallet’s chain ID, RPC endpoint and display details, and how to check that a network entry reaches the intended chain.

The Chain Times DeskOct 21, 2026 · 18:30 UTC3 min read

Chainslist helps frame a basic developer task: setting a wallet to reach the right blockchain. The settings connect a human-readable network name to a chain ID and one or more RPC endpoints—servers that handle wallet requests. The Ethereum wallet standard EIP-3085 defines fields developers may provide when asking a wallet to add a network. A good setup makes the network clear to the user and gives the wallet a working route to it.

What does chainslist mean for wallet network settings?

For developers, a network entry is a small bundle of details that must agree. EIP-3085 names the chain ID, RPC URLs, network name, native currency and block explorer URLs as possible fields. The chain ID identifies which chain a signed transaction targets; the display name and currency help a person recognise the selection. When checking a chainslist entry, developers can compare these pieces against the network they intend to support.

These fields do different jobs. The RPC endpoint is the wallet’s connection to a node, which reads chain data and sends transactions. The explorer address gives users a way to view transactions and addresses. The currency symbol is a display label; it does not prove that the wallet is connected to the intended chain.

How should developers choose a chain ID and RPC endpoint?

Start with the chain’s documented ID, then choose an endpoint that serves that same chain. EIP-155 uses chain IDs in transaction signing to help prevent a signed transaction from being replayed on a different chain. EIP-695 says wallets and apps can query `eth_chainId` to identify the chain reported by an endpoint.

EIP-3085 requires a wallet to reject an add-network request when the submitted ID does not match the ID returned by an RPC endpoint. It also warns that endpoints may be faulty, dishonest or expose a user’s activity and IP address. That makes the endpoint a security and privacy choice, not just a connection detail.

Which network details should an app check?

Before asking a wallet to add a network, developers can check the following against the chain’s own published information:

  • Chain ID: Use the intended chain’s ID and confirm the endpoint reports it through `eth_chainId`.
  • RPC URL: Confirm it is valid, uses HTTPS and serves the intended chain.
  • Currency details: Check the name, symbol and decimal setting used for balances and fees.
  • Explorer URL: Make sure it points to an explorer for the same chain.

EIP-3085 also says adding a network does not necessarily select it in the wallet. The app should handle that as a separate step and make the active network clear. For most users, the better choice is a familiar, verified endpoint with matching network details; adding more endpoints is useful only when the app needs a backup or a distinct provider. That is the practical lesson behind chainslist: matching fields is the start, and checking what the wallet actually connects to is the finish.
