Token Approval Revocation: Checking the Allowance

To check if a token approval was revoked, wait for confirmation, then read the ERC-20 allowance for your wallet and spender on the same network; zero means none remains.

The Chain Times DeskNov 20, 2026 · 20:57 UTC3 min read

After the revocation transaction confirms, check the ERC-20 token’s allowance for your wallet and the original spender on the same network; a value of zero means that spender has no current approved amount. Start with the transaction or wallet activity, then read the allowance on the token contract or a trusted checker. Make sure the token, wallet, network and spender match the original approval.

For a trade on SyncSwap, use the spender address shown in that approval record; spender addresses can differ across supported networks. For the matching MetaMask steps, see how to revoke SyncSwap approvals in MetaMask.

Confirm the revocation on its original network

A revocation only counts for this check after its transaction confirms on the network where the token resides. Use the transaction hash or your wallet’s activity to find the revocation and wait for confirmation. A pending transaction has not yet established the updated allowance on-chain.

Then open the token contract on that network’s block explorer, or use a trusted allowance checker. You need the token contract address, your wallet address and the spender address from the original approval. The token contract records an allowance for each wallet and spender pair, so the right addresses matter.

Read the allowance for the original spender

Read allowance(owner, spender) using your wallet as the owner and the original spender address. A zero value means that spender currently has no approved ERC-20 amount for your wallet. A nonzero value means some allowance remains, even if the revocation transaction appears in your activity.

Take the same token, wallet, spender and network in two cases. In one, the confirmed allowance reads zero, so the spender has no current allowance. In the other, it reads a nonzero amount, so an allowance remains. The deciding factor is the current value returned by the token contract.

A later approval can change that value. A signed permit can also grant token spending without a separate on-chain approval transaction. So a transaction history alone may not show every way an allowance was granted. Alongside transactions, review token activity and any signature prompts; compare their timing with the allowance reading. A later approval or permit may explain why a value is no longer zero.

Related questions

How do I check a token allowance on a block explorer?

Open the token contract’s read functions and query allowance with your wallet address and the spender address. Confirm the explorer is showing the network where the approval was made.

Why does a revoked token approval appear again?

A later approval or permit may have granted a new allowance. Check the transaction or signature and its timestamp, then read the current allowance again for the same wallet and spender.
